课堂笔记系统 · 使用说明

一台笔记本 + 一部手机，把英文课堂变成「可复习的中文笔记 + 自动排期的记忆卡」。笔记是一份三栏工作台网页：左边切视图、中间看内容、右边查工具。全部数据都在自己电脑上（仅「转写稿 → 结构化笔记」这一步会调用 DeepSeek）。

它由四块拼成

① 本土转写引擎whisper.cpp + large-v3-turbo
跑在你显卡上，离线免费
② 笔记生产make-notes.js
DeepSeek 加工成中文笔记
③ 笔记成品单文件 HTML 三栏工作台
8 个视图、6 套主题、可打印
④ 复习调度notes-cards.js → 学习台
FSRS-6 自动排期

日常就三步

1 · 上课：听 + 录音

  • 坐前 1/3，手机放桌上、麦克风朝讲者：这一步对准确率的影响比任何软件设置都大（实测：远场录音信噪比只有 8.7 dB，近场能到 25 dB 以上）。
  • iPhone 用「语音备忘录」录音即可；关掉任何“人声增强/降噪”开关（会削掉弱音节，反而更难转写）。
  • 实时理解可用手机同声传译 App 兜底，但别一直低头看屏幕，听课仍以听为主。

2 · 课后：双击一次，全套产出

把录音从手机传到电脑（微信文件传输助手 / iCloud）
   → 丢进  <项目文件夹>\录音\
        · 攒了几天的可以一起丢：一键流程会把「所有待处理音频」逐个跑完并汇总
        · 想更保险，就丢进以课程命名的子文件夹（录音\DEMO1006M\）——文件夹名会当作课名，
          且命中模块时会自动对齐成课表里的规范名
   → 双击  一键出笔记.cmd
   → 等 3~4 分钟／每个文件（一小时课；两小时连堂约 8 分钟）
   → 浏览器自动弹出笔记 HTML

这一下会自动完成：转码 → 本地转写 → 自动定课程名（规则见下节）→ DeepSeek 生成笔记 → 同步复习卡到学习台；结束后音频自动移进 录音\已处理\，回听副本进 音频\。

四份产物都按「课程」分文件夹，同一门课的笔记、转写稿、回听副本、原始录音各在一处，打开就是这个样子：

笔记\DEMO1013M Communication for EPS\DEMO1013M_Communication_for_EPS_2026-09-22.html
录音稿\DEMO1013M Communication for EPS\DEMO1013M_Communication_for_EPS_2026-09-22.txt
音频\DEMO1013M Communication for EPS\DEMO1013M_Communication_for_EPS_2026-09-22.m4a
录音\已处理\DEMO1013M Communication for EPS\DEMO1013M_Communication_for_EPS_2026-09-22.wav

实测（同一台机器、同一套参数）：26.5 分钟的真实课堂录音，转写只需 47~59 秒（≈ 27~34× 实时）；105.3 分钟的双节连堂（中间含 10 分钟课间）分段转写全程 7 分 20 秒——whisper 纯转写 184.5 秒（≈ 34× 实时），其余是逐段体检、滤镜与切段；其中课间那一段自动试满 6 档、清掉 19 处循环碎片后按原样保留，好段各只跑一次。DeepSeek 生成笔记占 40~90 秒。所以一小时课整链约 3~4 分钟，两小时连堂约 8 分钟。

它会怎样归档（全自动）

2026-09-29 起：一节课一个日期文件夹。同一天的四处产物永远在同一个日期文件夹里（文件夹名＝上课日期，拿不到才用生成日期），四个目录结构一致：
笔记\<课程>\2026-09-29\…html|.md|.json　·　录音稿\<课程>\2026-09-29\…txt|.srt　·　音频\<课程>\2026-09-29\…m4a　·　录音\已处理\<课程>\2026-09-29\…m4a|wav
备份统一收在 笔记\<课程>\_备份\（不再散在课程根目录）；课件则是每份各进一个自己的文件夹：整学期总课件放 课件\<课程>\总课件\（与日期文件夹并排），单节课件按日期进 课件\<课程>\<日期>\（文件名里的日期 → 课件到货时间 + 课表进度：按「这门课已做到哪一节、下一个还没有课件的讲座日就是它」推断，文件名里的周号只在和到货时间对得上（≤4 天）时才采信，对不上会打一行 ⚠ 并按进度归位 → 这门课最近一份笔记的上课日期 → 都没有才进 无日期\）。课程根目录只留课程级成果（共享课程地图 + 近似课程对比）。

  • 转写稿→ 录音稿\<课程>\<上课日期>\<课程>_<日期>.txt（先落盘。就算后面生成笔记失败，转写也不用重做）
  • 笔记→ 笔记\<课程>\<上课日期>\<课程>_<日期>.html（+.md 备份 +.json 数据；笔记重跑会落回同一个日期文件夹、同名覆盖）
  • 回听副本→ 音频\<课程>\<上课日期>\<课程>_<日期>.m4a（笔记里点 [mm:ss] 就跳到这里）。录音是 WAV 时会自动转成压缩 m4a（实测 145 MB → 19 MB），笔记照常带播放器
  • 原音频→ 自动移进 录音\已处理\<课程>\<上课日期>\（放在子文件夹里的也一样会被归档），收件箱保持干净
  • 复习卡→ 每次自动写入 English Learning\notes-cards.js（学习台按 F5 就能看到）。想挑卡：生成完会自动弹出选卡页（也可随时双击 选卡.cmd），取消勾选的卡会写进 不加入学习台.json，之后每次重建都不会再冒出来。选卡页底部还有「排除清单体检」：排除清单的 key 里嵌着原文，笔记一旦重新生成、说法变了，那条排除就会失效、卡片会悄悄回到词库（同步时会报「清单已失效 N 条」）—— 那一块逐条列出失效项、按相似度给出候选，可以一键接回或删掉，也能对生效中的排除点「放回」
  • 课件核对→ 若 课件\<课程名>\ 里有这门课的幻灯片，会额外做一次「录音 × 课件」对账：术语/数字/公式以课件为准，并把「课件里有、笔记没覆盖」的要点也列出来（实测抓出过讲者口头补充的「停机问题」和参考书的精确章节）
  • 转写质检→ 转写完自动扫一遍时间轴：同一句重复 ≥3 次、>8 秒空白、英文稿混入中文都会提示；确凿的幻觉段会被直接剔除，不送进模型（内置质量闸门只看重复次数，抓不到「静音处编话」，这一步补的就是它）
  • 长录音分段→ 超过 20 分钟的录音会先切成约 10 分钟一段、逐段判定质量：好的段一次就过（不再是整条反复重试），坏段先清掉循环重复的碎片、确实没人声的那段（例如课间休息）整段丢弃，最后把各段拼回一份完整转写稿，时间轴自动接上

3 · 复习：两处地方

  • 当天：打开笔记 HTML，左栏切到「复习问答」自测（点一下题面或按空格显示答案、←→ 翻题），再扫一遍「核心要点」。
  • 长期：打开 English Learning\学习台.html，分类里选「课堂笔记 · 课程名」或「课堂笔记问答 · 课程名」，让 FSRS-6 按遗忘曲线排期。

笔记页面长什么样：三栏工作台

笔记不是一份从上滚到底的长文档，而是一个带视图台的工作台：左栏选看哪个视图，中栏只显示那一个视图，右栏是随课生成的查询工具。

顶栏（吸顶）　标题（带朗读按钮）· 一句话概括 · 播放器 · 打印·PDF · 六套主题圆点
左栏 · 本课视图
  1. 核心要点
  2. 结构化笔记
  3. 中英对照
  4. 术语表
  5. 思维导图
  6. 复习问答
  7. 待办
  8. 课件核对

每项右边带条目数；下面还有「同门课其它讲次」和本课元信息（日期、时长、发言人数…）。

中栏 · 内容

当前视图的标题（左栏点哪个就在这显示哪个）；已去掉原来的面包屑——左栏本来就高亮着当前视图，重复。

一次只显示一个视图——点左栏就换，页面不会滑很长。窄屏（<1020px）自动退回「全部展开」的文档流。

右栏 · 学习工具

术语快查：输入英文或中文即时筛选（现在右栏只留这一个工具）

底部状态栏　课程名 · 日期　｜　空格显示答案 · ←→ 翻题 · 点 [mm:ss] 回听 · 点左栏切换视图　｜　要点 7 · 术语 26 · 问答 12 · 时间点 31
结构示意图（不是截图）：真实页面就是这三栏，配色跟着所选主题走。
底部状态栏是一条不透明的页脚，上沿带 22px 渐隐——正文滚到它下面会「溶进」背景，不会被切成半行、也不会透出文字（宽屏才吸底；窄屏自动退回成页面末尾的普通一行）。

八个视图各能做什么

视图能力
核心要点双栏 + 大号序号，每条带 [mm:ss]，30 秒扫完一节课
结构化笔记笔记的产出主体：按讲者的知识脉络分节（定义 → 原理 → 例子 → 易错点），长度不设上限；公式由离线渲染器把 LaTeX 转成 Unicode 与上下标（不引外部库）；识别存疑处标「存疑」
中英对照课堂原句 + 中文翻译，宽屏左右对照，每条可点读
术语表三线表：术语 / 中文 / 解释；标题旁有「连读本节」
思维导图可折叠树、分层底色；点方框展开收起，整块复制可粘进 XMind
复习问答问答卡：空格显示答案、←→ 翻题，带题目计数
待办真实复选框，勾选状态存在本机浏览器，带完成进度
课件核对拿老师的幻灯片给笔记对账，并把对不上的地方直接改对：逐项列出「笔记/录音里的说法」vs「课件里的说法」，并标结论——一致 / 以课件为准（笔记与课件有出入）/ 课件未提及（幻灯片上没有，可能是讲者口头补充）。
2026-09-30 起：标「以课件为准」的行会回改正文——核对那次调用顺便给出「原文片段 → 课件写法」的定向补丁，本地只对能唯一定位的片段做机械替换（找不到或有歧义就不动，并在表格备注里写明原因），每次回改都打印出来。左侧那一列永远保留录音原话，所以改了什么、原来是什么一目了然。想只要报告不改正文：加 --no-handout-patch。最后还会列出「课件里有、笔记没覆盖到的要点」。
把该课程的幻灯片放进 课件\<课程名>\ 就会自动做；没有课件时这个视图不出现。
2026-10-09 起：这节课没有新课件时（老师接着讲上一节没讲完的那份）会自动沿用最近一次日期文件夹里那份来核对，并在视图上方写一行「⚠ 课件来源：…」——免得你以为核对用的就是这节课的课件。老师若已发新课件，先双击 整理课件.cmd 再重跑本笔记就会换成新的
朗读（全局）标题、每条英文原句、每个术语旁都有喇叭按钮（内联 SVG，不是 emoji），点一下按英式发音读出来，再点停止
时间戳回听要点/对照/问答里的 [mm:ss]，点了就把内嵌播放器跳到原话位置——每条内容都能回查核对
左栏只列出「这次真有内容」的视图：某次课没生成待办，左栏就没有「待办」这一项，不是坏了。
直达某一节：地址栏加 #terms（或 #qa、#mindmap…）可以直接打开对应视图，也能把链接存成书签。
日期口径：左栏写「上课日期」时，那是从文件名或你给的 --date 得来的可靠日期，笔记文件名也用它；都没有时写「生成日期」（手机转码 m4a 里的时间标签实测是转码时刻，不作数）。
看不到新版式？按 Ctrl+F5 强制刷新。管线每次打开都会带一个版本号（?v=时间戳）绕开缓存，手工打开旧标签页时才会遇到。

命令速查

所有命令都在 <项目文件夹> 目录下执行（或不带参数的纯双击）。

命令作用
一键出笔记.cmd日常就用这个：取 录音\ 里所有待处理音频逐个跑完整流程（= node make-notes.js --all），处理完把音频移进 录音\已处理\，最后汇总成功/失败个数
生成笔记.cmd只重跑「笔记生成」：取 录音稿\ 里最新的 .txt，用最新转写稿重新生成（不重新转写，文件名不变）
node make-notes.js只处理最新的一个音频（不扫全收件箱）
node make-notes.js --stats "某.m4a"只体检不转写：看电平/信噪比/静音占比，判断这间教室收音好不好
node make-notes.js --audio "某.m4a" --only只转写，不生成笔记
node make-notes.js --file "录音稿\x.txt" --course "课名"指定转写稿 + 指定课程名（决定文件名与卡片分类）
node make-notes.js --audio "某.m4a" --date "2026-09-25 13:05"文件名没有时间信息时，手动告诉它这节课的时间。给了就会按课表定时段并据此定名；只给日期也行（--date "2026-09-25"），此时只补日期、不猜时刻、也不对课表
node make-notes.js --build-prompt重建术语提示（从历史笔记 + terms-manual.txt 汇总成 whisper\prompt.txt）
node make-notes.js --check测 DeepSeek key 与网络通不通
node make-notes.js --where显示它到底从哪个文件读到了 key
node make-notes.js --mock --no-sync离线自测：用样例数据渲染一份笔记，不联网、不花钱（改模板时用它迭代）
node sync-fsrs.js单独重新同步复习卡（一键流程里已自动执行）
周复习.cmd把本周所有笔记汇总成一页「周复习台」（课程卡片 + 知识地图 + 术语汇总 + 跨课抽查 15 题 + 待办）
选卡.cmd挑卡：打开选卡页，逐张勾选哪些课堂卡进英语学习台（默认全勾）。取消勾选的会写进 不加入学习台.json，以后每次重建都尊重它。一键出笔记流程结束后会自动打开一次
node weekly-review.js --list看看哪几周有笔记
一键出笔记.cmd --model "…\ggml-large-v3-turbo-q5_0.bin"只这一次换模型（更省显存；详见下方「换模型」）

课程名怎么来的（不用你起名）

笔记文件名与复习卡分类都靠「课程名」组织。系统按下面的顺序自动决定，前面命中就不看后面：

顺序来源怎么用
1--course "课名"显式指定，永远最优先
2课程表按时段匹配（唯一）时间来源可靠时（文件名自带日期时间，或你用 --date 指定），按星期 + 时间 + 教学窗口对到课表课时——最客观，唯一命中就直接用
3课程.json 记住的名字上次用的名字（含你手工订正过的）——同一文件名第二次处理自动沿用
4录音所在子文件夹名如 录音\DEMO1006M\；命中模块会自动对齐成规范课名。注意：课表时段（第 2 档）优先级更高，所以「10月」「未整理」这类组织用文件夹不会污染课名
5AI 按内容从课表认课没有时间线索时，课程表随转写稿一起交给模型，命中就返回「代码 + 名称」——与生成笔记是同一次请求，不额外花钱
6AI 自起名 / 音频文件名都不匹配（讲座、说明会、活动）时兜底；「未指定」这类占位词会被拒绝，改用下一档

时间怎么自动定时段

  • 录音文件名带日期时间（如 录音_20260929_110512.m4a）时，按星期 + 时间对 slots；只有唯一命中才直接采用课表名，多门撞同一时段就交给 AI 按内容判。
  • 文件名没带时间时，可以用 --date 手动补上，效果与文件名带时间相同（会去课表定时段并据此定名）。另外：手机转码过的 m4a 确实带 creation_time 标签，但实测它是转码时刻不是录制时刻（两份录音各 37 分钟，标签只差 9 秒），所以管线不采信它。
  • 学期自动区分：9–12 月＝第一学期，1–5 月＝第二学期（你的课表里周二 11:00 两学期都有课，靠这个不会串）。
  • 第一学期：termStart = 2026-09-28（你确认过，与官方一致）→ 周次过滤已开启：第 0 周＝迎新周（9/21–9/27），第 1–11 周为教学周，官方教学期 2026-09-28 ～ 12-11。
  • 第二学期：官方教学期 2027-01-25 ～ 2027-05-07（leeds.ac.uk/term-dates 2026/27）。PDF 里的「14–24 周」夹着复活节闭校（21 周之后直接跳 22 周），无法换算成日期，所以第二学期不用周次过滤，只按星期 + 时间 + 教学窗口匹配。
  • 教学窗口外一律不按时间匹配：圣诞假（12/24–1/1）、第一学期结束后、第二学期结束后、暑期 6–8 月、以及学期之间的空档。这时交给 AI 按内容起名，避免假期里的录音被误配成某门课。
  • 课表不填也不影响使用：这一段自动跳过，退回「AI 自己起名」。
为什么不能只看时间？手机录音的容器里经常没有录制时间——实测你那份 m4a 里就没有，Windows 显示的创建/修改时间是你拷进电脑的时间（那份文件显示 00:25，而课是白天上的）。所以只有「文件名自带日期时间」才用它定时段，其余情况交给 AI 按内容认课。

换模型（可选）

本机现有两套可用的转写模型，可随时切换、互不影响：

模型体积速度（实测）适用
ggml-large-v3-turbo-q8_0.bin（当前默认）834 MB26.5 分钟录音 → 47~59 秒（≈27~34× 实时）日常默认：比 q5_0 精度略高，速度几乎一样
ggml-large-v3-turbo-q5_0.bin547 MB略快，约 29× 实时更省显存；显存紧张时切成它

只这一次用别的模型

把录音丢进 录音\  →  运行：
一键出笔记.cmd --model "D:\path\to\whisper\models\ggml-large-v3-turbo-q5_0.bin"

长期切换成默认

改本目录的 config.json（路径按需改）：

{
  "model": "D:\\path\\to\\whisper\\models\\ggml-large-v3-turbo-q5_0.bin",
  "diarize": false
}

现在这份 config.json 已经把默认固定成了 turbo-q8_0（上面第一行就是它）。若删掉 config.json，管线会按内置顺序自己挑：先 q5_0，再 q8_0。

关于显存（重要实测结论）：turbo 档（834 MB / 547 MB）在你的 4 GB 显存上都很稳。真正会翻车的是那个 1.5 GB 的 ggml-large-v3-q8_0.bin——空载时能跑（10× 实时），但浏览器等程序占用显存后，驱动会把它挤到系统内存，速度暴跌到 0.4× 实时（慢 40~66 倍），同一段音频耗时在 12 秒到 193 秒之间跳。它和 2.9 GB 的量化源文件 ggml-large-v3.bin 已于 2026-09-22 一并删除，不要再去找。
管线内置两层保护：①单次卡死保护——某一次转写超过「这一段时长 ÷ 2」秒（至少 90 秒）仍未完成，就终止并换下一个参数档/模型；②长录音分段（2026-10-13 起）——超过 20 分钟的录音切成约 10 分钟一段、逐段判定质量，所以不会再出现「105 分钟里只有 8 分钟有杂音 → 整条重试十几遍、磨 50 分钟」的情况。

周复习台 & 发言人分离

周复习台（每周一次，复习用）

  • 双击 周复习.cmd，会把本周所有笔记合成一页：课程卡片（含当日笔记链接）、知识地图（各课导图第一层）、术语汇总（去重 + 出处）、跨课抽查（每周随机抽 15 题）、待办汇总。
  • 产物在 课堂笔记\复习台\<年>-W<周>.html，同样是六主题、双击即开。
  • 它只汇总同一周的笔记；node weekly-review.js --list 可以先看哪几周有内容。

发言人分离（实测结论：不可用，保持关闭）

  • 默认关闭。加 --diarize 开关，或在本目录 config.json 里写 {"diarize": true} 常开。
  • 它会多产出一份 讲者稿（[时间] 主讲/其他人：句子）。长录音需要几分钟（CPU 推理）。
  • 两次实测都没法用：8.7 dB 的远场录音覆盖率 36%；即便信噪比好到 15.2 dB 的导师小组讨论，也是 覆盖率 49%、分出 107 位发言人（实际只有 6~8 人），连导师本人的开场独白都被标成「其他人」。
  • 所以现在：覆盖率低于 60% 时，笔记里不再报「N 位」这个数字，直接写「分离不可靠」；讲者稿顶部也会加警告头。别指望它告诉你「谁在说话」。

已知边界（诚实版）

  • 长课会拆成多段分别生成再合并：拆分阈值 1.8 万字符（约 25 分钟一段）——每段有独立的 8000 token 输出预算， 所以课越长、段越多，笔记正文能写得越厚（实测 95 分钟的课分 5 段，正文从 3,911 加厚到 9,153 字符）。 代价是 API 次数按段数增加；正文里会看到「【第 N 部分】」的分隔标记。
  • 静音处可能凭空编话：实测一份 38.3 分钟的讲座，开头 1 分 40 秒（录音里没人说话）被编出整段假台词，英文稿里还蹦出中文。管线现在会自动质检并剔除确凿的幻觉段；但笔记生成后仍建议拿 3–5 条断言回 grep 转写稿核对（实测模型会自己跳过首尾垃圾，可仍值得核一次）。
  • 人名地名仍会错：8.7 dB 信噪比的远场录音里，“某位老师”被转成“DeCone”、Parkinson 被转成 Atkinson。软件救不回来，只能靠坐近 + 术语表补。
  • 发言人分离不可用：引擎已装好（sherpa-onnx，离线、无需 token），但两次实测（8.7 dB → 覆盖率 36%；15.2 dB → 覆盖率 49% 且分出 107 位）都不靠谱——笔记里已改为直说「分离不可靠」，不再报数字。
  • 时间戳依赖音频文件：内嵌播放器引用 课堂笔记\音频\ 里的副本；若删掉该副本，时间戳仍显示但点击不会再跳转。
  • 音频不离开本机，但转写稿会发给 DeepSeek 做笔记——介意的话可以只用 --only 拿转写稿。
  • 课名不是 100% 保证正确：文件名带日期时间的录音是确定性匹配（星期+时间+教学窗口 → 课表课时）；文件名不带时间时靠 AI 读内容从课表里认课，偶尔会认错（实测把它认成过模块课）。所以每次生成后扫一眼笔记文件名；认错了就编辑 课程.json 把课名改成正确的，下次同名文件自动沿用。
  • 课件只能提文字：你这门课的 299 页课件**每页都有文字层**，所以全提得到；但纯图片/扫描版幻灯片提不到内容（本机没有视觉模型）。图片里的示意图、表格截图，只能靠录音里的讲解补。
  • 课件核对不是逐字比对：它挑的是术语/数字/公式/定义这类对不上就要出事的地方（实测一份 95 分钟课核出 29 项），不是把整份课件逐句比一遍。判成「课件未提及」的意思是幻灯片上没有——可能只是老师口头补充（那种往往是考点），也可能是课件里放在别的讲。
  • 失败的文件会留在 录音\ 里：太短/没声音的录音会被跳过（提示「转写稿只有 N 字符」），批量结束后会汇总成功/失败个数。误录的空文件自己删掉即可；真课重跑很便宜（转写稿已存）。
  • 课表是暂定的：PDF 自己写着 provisional，而且第一学期目前只公布出 DEMO1006M 与 DEMO1001M 的讲座。开学后课表若更新，把新 PDF 发我重新提取。
  • 键盘还没做全：目前只有问答页的空格（显示答案）与 ←→（翻题）。1–7 切视图、/ 聚焦术语快查这些还没有。
  • 没有自动视觉回归：设计底线靠 _verify-output.js 的 41 项断言 + 人工截图复核；改版式后建议在真实笔记上截图确认一遍。
  • 录音需老师同意（利兹政策），且只作个人学习用途。
